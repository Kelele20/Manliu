# 漫流架构设计

本文档描述漫流（Manliu）的代码架构、模块职责和关键设计决策，供开发者快速理解项目全貌。

## 架构总览

漫流采用**单 Activity + Compose 导航**的架构，整体分为四个层次：

## 数据模型

### Room 实体

```
ComicAlbum (albums)
├── id: Long (主键, 自增)
├── title: String
├── createdAt: Long
├── sortOrder: Int          ← 拖拽排序位置
├── progressPage: Int       ← 阅读进度（页索引）
├── progressOffset: Int     ← 阅读进度（滚动偏移）
└── progressPageId: Long    ← 阅读进度（稳定页面 ID）

ComicPage (pages)
├── id: Long (主键, 自增)
├── albumId: Long → albums.id (级联删除)
├── position: Int           ← 排序位置
├── fileName: String        ← 应用内文件名
├── originalName: String    ← 原始文件名
├── width / height: Int     ← 图片尺寸（含 EXIF 旋转校正）
├── chapterTitle: String?   ← 旧版章节标记（已废弃显示）
└── importItemId: Long?     ← 关联导入项（用于重试插入位置计算）

ImportJob (import_jobs)
├── id: Long (主键)
├── albumId: Long → albums.id (级联删除)
├── folderUri: String       ← 来源（文件夹 URI 或 "staged:{uuid}"）
├── status: String          ← PREPARING / QUEUED / RUNNING / PAUSED / DONE / CANCELLED
├── total / processed / imported / failed: Int
└── message: String?

ImportItem (import_items)
├── id: Long (主键)
├── taskId: Long → import_jobs.id (级联删除)
├── sequence: Int           ← 原始选择顺序
├── uri / name / sizeBytes
├── status: String          ← PENDING / DONE / FAILED
└── error: String?
```

### 轻量查询模型

```kotlin
data class AlbumOverview(id, title, progressPage, pageCount, coverName)
```

首页列表使用 `AlbumOverview` 子查询，只加载封面和数量，避免加载整个图集的所有图片记录。

## 核心模块详解

### 1. ComicRepository — 业务逻辑中枢

**单例模式**，通过 `ComicRepository.get(context)` 获取。负责：

| 职责 | 关键方法 |
|------|----------|
| 图集 CRUD | `createAlbum()`, `deleteAlbum()`, `reorderAlbums()` |
| 图片导入 | `importImages()`, `createFolderImport()`, `createSelectedImport()` |
| 导入任务队列 | `prepareNextImport()`, `processNextImport()`, `pauseImport()`, `resumeImport()` |
| 图片管理 | `reorderPage()`, `sortPagesByName()`, `deletePage()`, `deletePages()` |
| 阅读进度 | `saveProgress()` |
| 文件操作 | `imageFile()`, `albumDirectory()`, `copyAndInspect()` |

**设计要点**：

- **事务安全**：所有涉及多表操作均使用 `database.withTransaction {}` 保证原子性
- **EXIF 旋转校正**：`copyAndInspect()` 在复制图片后读取 EXIF 方向信息，交换宽高
- **空间预检查**：导入前检查可用空间，预留 32 MB 余量
- **暂存机制**：相册/文件选择的图片先暂存到 `import-staging/` 目录，防止系统回收 URI 授权

### 2. ImportService — 图片导入服务

**前台服务**（`foregroundServiceType="dataSync"`），职责：

1. 接收「多选图片」或「文件夹导入」请求
2. 按队列依次处理：先暂存（`prepareNextImport`），再导入（`processNextImport`）
3. 通知栏显示进度
4. 处理 Android 15 的 `onTimeout()` 限制：自动暂停运行中的任务

**导入流程**：

```
用户选择图片
    ↓
createSelectedImport() / createFolderImport()
    ↓ 写入 import_jobs + import_items
ImportService 启动
    ↓
prepareNextImport()        ← 暂存阶段（仅相册/文件多选需要）
    ↓ 将 picker URI 复制到 import-staging/ 目录
processNextImport()        ← 导入阶段
    ↓ 逐张复制到 albums/{id}/ + 写入 pages 表
    ↓ 计算插入位置（importInsertionPosition）
完成 / 失败项可重试
```

### 3. ArchiveManager + ArchiveService — 备份恢复

**备份格式**：`.manliu` 文件 = ZIP（无压缩）+ `manifest.json`

**导出流程**：

```
读取图集和页面 → 验证限制（ArchiveLimits）→ 生成 manifest.json
→ 打开输出流（验证通过后才打开）→ 逐张写入图片 → 完成
```

**恢复流程**：

```
读取 ZIP → 解析 manifest → 验证限制 → 暂存图片到 restore-staging/
→ 事务写入数据库（新增图集，不覆盖）→ 移动图片到 albums/ → 清理暂存
```

**关键设计：先验证后打开**

`ArchiveLimits.openAfterValidation()` 确保所有校验通过后才打开目标文件，避免导出失败时留下截断的文件。

### 4. DragReorderState — 拖拽排序引擎

基于 Jetpack Compose 的 `LazyColumn` 实现长按拖拽排序：

| 组件 | 职责 |
|------|------|
| `DragReorderState` | 状态机：维护拖拽中的临时顺序、偏移量计算、自动滚动 |
| `Modifier.dragReorder()` | Compose Modifier：接管长按手势，触发拖拽 |
| `DragHandle()` | UI 组件：「≡」拖动手柄 |

**工作原理**：

1. **长按启动**：检测右侧手柄区域的长按手势
2. **拖拽中**：实时更新 `dragTop`，当中心点越过相邻项时交换位置
3. **自动滚动**：靠近列表边缘时按距离比例加速滚动
4. **松手提交**：返回 `DragDrop(movedId, orderedIds)` 由 Repository 持久化
5. **等待保存**：`waitingForSave` 状态阻止新拖拽，直到 Room Flow 发射匹配顺序

### 5. 辅助算法

#### ImageSorting — 自然文件名排序

`compareImageNames()` 实现自然排序：数字按数值比较，非数字按字符比较。

```
排序结果：1.jpg → 2.jpg → 10.jpg → 100.jpg
而非字典序：1.jpg → 10.jpg → 100.jpg → 2.jpg
```

#### ImportOrdering — 重试插入位置

`importInsertionPosition()` 计算失败重试时的插入位置，优先插到原始相邻兄弟旁边：

```
优先级：紧接的下一个成功项位置 > 上一个成功项 + 1 > 追加到末尾
```

#### ReaderProgress — 阅读位置恢复

通过稳定的页面 ID（而非索引）保存阅读位置，插入或删除图片后仍能恢复到正确页面。

## UI 导航

采用手动状态管理的简单导航，不使用 Navigation 组件：

```kotlin
var destination by rememberSaveable { mutableStateOf("library") }

when (destination) {
    "library" → LibraryScreen(...)   // 首页：图集列表
    "album"   → AlbumScreen(...)     // 图集详情：图片管理
    "reader"  → ReaderScreen(...)    // 沉浸式阅读
}
```

### 页面功能一览

| 页面 | 功能 |
|------|------|
| **LibraryScreen** | 图集列表、新建图集、拖拽排序、备份全部/恢复、开始/继续阅读 |
| **AlbumScreen** | 图片列表、添加图片（3 种来源）、拖拽/文件名排序、批量选择/删除、导入进度卡、单图集备份 |
| **FolderImportDialog** | 文件夹图片预览、全选/排序（名称升序/降序/最近修改）、空间预估 |
| **ReaderScreen** | 连续滚动阅读、页码跳转、实时观察图片变化、工具栏切换 |

## 文件存储

```
应用专属目录（filesDir）
├── albums/
│   ├── {albumId}/
│   │   ├── import-{itemId}.jpg    ← 文件夹导入的图片
│   │   ├── {uuid}.jpg            ← 相册/文件导入的图片
│   │   └── ...
│   └── ...
├── import-staging/
│   └── {batch-uuid}/             ← 多选图片暂存（导入完成后清理）
│       ├── 0
│       ├── 1
│       └── ...
└── restore-staging/              ← 恢复暂存（恢复完成后清理）
    └── {uuid}/
        └── a{n}/
            └── {n}.{ext}
```

- 导入的图片**复制**到应用专属空间，原图删除不影响
- 卸载应用会清除所有应用内副本
- 暂存文件在任务完成或取消后清理，中断后下次启动也会清理孤立暂存

## 线程模型

| 操作 | 线程 |
|------|------|
| Room 查询（Flow） | Room 内部线程 |
| Repository 方法 | `Dispatchers.IO`（通过 `withContext`） |
| ImportService | `SupervisorJob() + Dispatchers.IO` |
| ArchiveService | `SupervisorJob() + Dispatchers.IO` |
| UI 状态 | Compose 主线程（通过 `collectAsState`） |

所有 Repository 的 `suspend` 方法内部切换到 `Dispatchers.IO`，调用方无需关心线程。

## 设计原则

1. **离线优先**：不依赖网络，不声明网络权限
2. **数据安全**：事务保护多表操作，异常时回滚并清理已移动的文件
3. **先验后写**：备份导出先完成所有校验再打开目标文件
4. **渐进式容错**：导入失败的图片标记为 FAILED 但不阻断整体任务，可单独重试
5. **空间感知**：导入前预估空间需求，操作中持续检查可用空间
6. **进度可控**：所有长时间任务支持暂停、继续和取消
