# 漫流使用与开发说明（v0.3.3）

## 版本与升级

- [下载 v0.3.3 正式版 APK](https://github.com/Kelele20/Manliu/releases/tag/v0.3.3)。[v0.3.0 旧版](https://github.com/Kelele20/Manliu/releases/tag/v0.3.0)仍可在 Releases 中获取。
- v0.3.3 与 v0.3.2 使用相同签名，可直接覆盖安装。升级前建议先从首页菜单备份重要图集；不要先卸载旧版，卸载会清除应用内图片和数据库。
- 仓库为私有仓库，下载需要有权限的 GitHub 账号。
- 开发签名密钥 `manliu-dev-key.keystore` 单独保存在私人位置，不在 Git 仓库或 Release 中。使用不同签名的 APK 不能覆盖安装。要用同一签名构建，把原密钥文件放在项目根目录。

## 导入图片

### 按文件夹批量导入

1. 点击「新建图集」→「添加图片」→「从文件夹选择 · 全选/排序」，选择**含图片的子文件夹**。
2. 预览中按「全选」或逐张勾选。可按名称自然升序（如 1、2、10）、名称降序或最近修改时间排序；一次最多选 10000 张。点击「导入」后会检查已知图片大小及可用空间，再启动后台导入。
3. 图集页的导入进度卡显示已处理、成功和失败张数。可暂停、继续或取消；取消后已导入图片会保留。任务中断后重新打开图集，可点「继续导入」或「尝试恢复」。在「失败清单」查看错误原因，再点「重试失败项」；失败项会按原始导入顺序插入。

### 从相册或文件选择

在图集页点击「添加图片」，选择「从相册选择」或「从文件选择」。每批最多导入 100 张，超过部分需分批选择；相册系统选择器可能按设备进一步限制数量。单张图片不得超过 100 MiB。多选任务会保存到本机并通过前台服务继续处理，离开图集页或切换到阅读页后仍可运行；通知栏会显示进度。返回该图集即可查看任务，暂停、继续或取消，之后也可查看失败清单并重试。一个图集存在未完成任务时，需先继续或取消该任务再开始新的导入。

多选图片需要先从系统选择器暂存到漫流的应用目录。若系统在暂存完成前终止任务，且重启后原 URI 授权已失效，对应图片会失败，需要重新选择。来自云盘等文件提供方的图片在暂存期间必须保持可访问。文件夹选择只读取所选文件夹当前层级，不递归读取子文件夹；文件提供方未报告大小时，空间预估可能偏低，空间不足时先清理空间再继续。

Android 11 及以上限制普通应用直接读取 `Android/data`，系统选择器也不能直接选 `Download` 根目录。可先用手机自带文件管理器将原图**复制**到 `Download/漫流待导入` 等子文件夹，再选该子文件夹。漫流会再复制到应用专属存储，确认导入成功后可自行清理中转文件。删除手机里的原图不会同步删除漫流副本，反过来也一样。

## 阅读与管理

- 长按右侧「≡」拖动图集或图片，靠近屏幕边缘可自动滚动；松手后保存顺序。图集页右上角菜单仍可按文件名升序或降序排序。点「批量选择」→「全选」→「删除所选」可删除多张应用内副本，原图不受影响。
- 首页点击图集卡片进入整理；点击卡片内「开始阅读／继续阅读」直接进入阅读页。图集页也可点击「开始阅读」。向上滑动连续阅读，点画面显示工具栏，点右上页码跳到指定页。
- 阅读页会实时观察图集和图片变化，后台导入的新图片会显示出来；阅读进度按稳定图片 ID 保存，插入图片后仍尽量回到原页。拖动、排序和删除后也会尽量保留正在阅读的图片；删除当前页时会跳到附近页面。旧版章节标记仍保存在旧数据库中，但 v0.3.3 不再显示章节或目录入口。

## 备份与恢复

- 首页右上角菜单中的「备份和恢复」可备份全部图集或恢复备份；单个图集菜单中的「备份这个图集」只导出该图集。备份文件扩展名为 `.manliu`，包含图集、图片、图片顺序和阅读进度。可将文件保存到系统文件管理器、云盘或移动硬盘。
- 恢复会新增图集，不覆盖现有图集。恢复仅支持漫流生成的 `.manliu` 备份，不支持普通 ZIP/CBZ 漫画包。旧版备份中的图片和顺序可以恢复，章节标记不会恢复。
- 创建和恢复备份采用相同上限：最多 1000 个图集、200000 张图片、64 MiB 备份清单、单张图片 100 MiB。导出会先检查这些限制，再打开目标文件写入；超限时会提示失败，不会先截断目标文件。

图片和数据库位于应用专属目录，卸载应用会删除它们。请把备份保存到应用外的位置；自动备份未开启。备份或恢复大量图片时要留出足够空间并等待完成。取消备份可能留下不完整文件，可在文件管理器中删除。

## 从源码构建

安装 JDK 17 与 Android SDK 35，在 Android Studio 打开仓库根目录，或执行：

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

Windows 用 `.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug`。APK 在 `app/build/outputs/apk/debug/app-debug.apk`。最低 Android 8.0，目标 Android 15。项目使用 Kotlin、Compose、Room 和 Coil；应用未声明自身网络权限。

Pull Request 的 GitHub Actions 与本地使用同一任务，运行 11 项 JVM 单元测试并构建 Debug APK。测试覆盖备份边界 5 项、导入顺序 4 项、阅读位置 2 项；不包含 Android 仪器测试。v0.3.3 Release 记录了用户真机试用反馈，未发现明显问题；上述导入、阅读和备份专项场景仍未逐项做设备验证，不能代表所有机型及异常流程均已覆盖。

仍待专项设备验证的场景包括：多选导入期间离开页面、旋转和暂停后恢复；暂存期间进程终止及 URI 授权失效；导入过程中阅读、后台新增图片和失败重试后的阅读位置；备份后再恢复的完整往返流程。
